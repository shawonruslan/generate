# v27.10 - fixes (desktop + app + generator + web panel)

## 1. App / desktop showed different metadata than the web panel
**Cause.** The Android app and the desktop app read Firebase over the REST *stream* (SSE). Firebase sends a
`keep-alive` every ~30 s, but when the socket dies silently (PC sleep/wake, Wi-Fi <-> mobile switch, VPN or
NAT drop, Android Doze) no error is raised - the local mirror simply stops updating and keeps showing the
**old** title / tags / category while the web panel (Firebase JS SDK, which detects dead sockets) is right.
The Android app had a second bug: a multi-location update (`{"<id>/title": ...}`) arrives as a `patch` whose
keys contain `/`; the app stored it as a bogus `"<id>/title"` child instead of updating the item.

**Fix.**
- Desktop `lib/data/firebase_rtdb.dart`: stream watchdog - no event for 75 s -> the socket is closed and
  reopened, Firebase then sends a fresh full snapshot (`put /`) so the mirror is re-synced. `Cache-Control:
  no-cache` added. The sidebar LIVE dot now really reflects the realtime link (`onConnection`).
- App `data/FirebaseRtdb.kt`: SSE read timeout 0 -> 90 s (dead socket -> reconnect + full re-sync);
  `patch` keys are split on `/`.
- Firebase data structure is untouched; nothing new is written.

## 2. Mix mode is now shown in the calendar (desktop)
When `dashboardSettings/variety.enabled` is ON for the active account the Schedule calendar plans every day
exactly like the bot (`zedgeN.yml` v25 variety block): each slot takes the next content type of the daily
rotated order (`types` rotated by the Dhaka day number) that has not been uploaded that day and has >= 1
queued file; empty types are skipped; `strict` -> the slot waits instead of repeating a type. Today's
already-uploaded types come from `uploadState/varietyUsed`. **Pinned items are unchanged** (they always win
and never count as a used type). The day strip shows `Mix mode · Ringtone › Wallpaper › Live Video`, the
legend shows `Mix Mode ON · order today`, and the "need 3 files" rule is not applied in mix mode.

**Safety.** This is read-only: `schedule_planner.dart` only *derives* the calendar. `saveSchedule` /
`saveVariety` still write exactly `dashboardSettings/schedule { windows, slots, updatedAt, updatedBy }` and
`dashboardSettings/variety { enabled, strict, types, updatedAt, updatedBy }` - the bot's gate ("Schedule
read") and upload run keep working. Files: `lib/domain/schedule_planner.dart`, `lib/data/models.dart`
(`varietyOrderForDay`), `lib/state/app_state.dart`, `lib/ui/screens/schedule_screen.dart`.

## 3. Generator ringtones: sound did not match the metadata
**Causes found in `generator.yml`.**
1. The Gemini reply was accepted after 3 s without change - while Gemini was still streaming. A half reply
   was parsed and the missing `[ENHANCED_PROMPT]` silently fell back to `"electronic synth pulse"`, so
   Stable Audio rendered a generic electronic sound while title/tags described the real concept.
2. The tag parser was strict: Gemini renders markdown, so `**[ENHANCED PROMPT]**`, `[ENHANCEDPROMPT]`,
   `[TITLE]:` or a missing closing tag all returned '' -> same silent fallback.
3. Stable Audio is a text-to-**music** model. Themes like *Lion Roar*, *Funny Sneeze*, *Keyboard typing*,
   *Thunderstorm*, *Robot voice* cannot be rendered realistically, yet the metadata promised them.
4. The real audio prompt was never stored, so nobody could see what the model had been asked.

**Fix.**
- `callGeminiWeb(..., { completeWhen })`: the reply is accepted only when it contains the closing tag of the
  last template section (`[/DESCRIPTION]`, `[/POLICY]` for images) and has been stable for 3 s (soft
  deadline 75 s).
- Tolerant tag parser (markdown bold, spaces/missing `_`, `:` after the tag, missing closing tag, literal
  `...` placeholder = missing).
- Missing `ENHANCED_PROMPT` / `TITLE` / `KEYWORDS` now **throws** -> the existing 3-attempt loop regenerates
  in a fresh chat instead of uploading a mismatched item. Missing `CATEGORY` -> OTHER, missing `DESCRIPTION`
  -> title (warned in the log).
- Alignment guard: if none of the tags appears in the audio prompt (stem match) the metadata is regenerated;
  the log prints `Metadata/audio alignment: n/10 tags found in the audio prompt`.
- `RENDERER_RULES` added to the Gemini prompt: what the music model can/cannot do, translate sound-effect
  themes into a musical equivalent, and describe *only* what the ENHANCED_PROMPT will literally sound like.
- Firebase item now also stores `enhancedPrompt`, `audioSeed`, `audioModel`, and `prompt` = the enhanced
  prompt when no user idea was given (visible as "Generation prompt" in panel / app / desktop).
- Same tolerant parser + complete-wait for the image metadata job.

Rebuild: desktop -> Actions "Build desktop app" (artifact `...-v27.10.0`); app -> `release-apk.yml`;
generator -> nothing to rebuild, the workflow file itself changed.

## 6. v27.10.2 - Web panel: clicking just below the account pill switched every account to "Zedge 1"
- **Cause:** the custom account dropdown (`#sunDropdown`) keeps its option panel in the DOM while closed
  (`opacity:0; pointer-events:none`). But the older z-index fix rule `.sun-dd-item { pointer-events: auto }`
  re-enabled hit-testing on the *invisible* option rows (an explicit `auto` on a child wins over the parent's
  `none`). The hidden panel sits 12 px under the pill, so the first invisible row - **Zedge 1** - caught every
  click in that area and fired a real `change` on `#activeZedgeAccount`.
- **Fix (all four `index.html`):** rows are click targets only while `.sun-dropdown.open`; the closed panel is
  additionally `visibility:hidden` (never a hit-target, regardless of other rules) with a delayed transition so the
  close animation still plays; and the item `click` handler ignores events unless the panel is really open.
  Account switching itself (`select.value = ...; dispatchEvent('change')`) is unchanged.
