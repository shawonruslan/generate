# v26.2 - Exact-time publish fix

## The problem
With an **Exact** slot (e.g. 05:20) the upload was landing 10-30 min late. Two causes:
1. **Gate bug** - an exact slot only became "active" *at* its minute, so the early ping (05:00) was treated as
   "outside" instead of sleeping until 05:20. The upload then ran on the *next* ping (05:30).
2. **Setup time** - even when the gate released at 05:20, checkout + Playwright install + login + content
   generation took 3-8 min before the Publish click.

## The fix (all zedge*.yml)
- The gate treats an exact slot as active one ping before its minute, so the early ping sleeps correctly.
- For exact slots the gate releases **EXACT_LEAD_MIN** minutes early (default **6**). Setup/login/generation happen
  during that lead.
- The gate passes the target (`HH:MM` Dhaka) to bot.js as `EXACT_TARGET_DHAKA`; bot.js **holds right before the
  Publish click** until that minute (+-1-2 s). Only the first publish of a run is held.
- If the run is already late (ping delayed by cron-job.org / GitHub queue) it publishes immediately - no double wait.
- Lead is adjustable per account: `dashboardSettings/schedule/exactLeadMin` (0-25). Increase it if your runs
  regularly take longer than 6 min to reach Publish (VPN + live wallpaper generation can).

## Requirements
- cron-job.org must ping every **30 min** (`0,30 * * * *`, Asia/Dhaka) as documented in the panel. With hourly pings
  an exact slot can still be up to 30 min late.
- Window (random) slots are unchanged.

## Logs to look for (Actions -> gate step / bot step)
- `decision: run (sleeping 14 min until 05:14, publish at 05:20)`
- `EXACT_TIME => holding 3.4 min so Publish lands at 05:20 Dhaka sharp.`
- `EXACT_TIME => 05:20 reached - Publish now.`


## v27.5 fix
- BUG: `waitForExactTarget` was defined inside vpn.mjs instead of bot.js -> `ReferenceError: waitForExactTarget is not defined` right before the Publish click, so the upload stayed as a DRAFT. Function moved into bot.js scope.
- Publish click is now robust: scrollIntoView + locator click, role-locator fallback, DOM click fallback, and it verifies the Publish button disappears (retries once). If it still cannot click, the run fails loudly instead of leaving a silent draft.
